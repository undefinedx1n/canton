# 人工预排 + 钉钉排班表导出

目标：满足两类需求，且**不改求解器、不改现有排班逻辑**。

1. 人工先预排（指定某人某天某岗）→ 系统补空；调班、请年假、临时指定休息都要能落地。
2. 导出「柯达广州塔排班表」格式（钉钉考勤排班导入模板），每次排完班提交人力。

---

## 一、人工预排：现有能力盘点

结论：**4 个场景里 3 个已经能跑，只缺"调班互换"**。不需要推翻重做，是在现有编辑能力上补一个动作。

| 场景 | 现有支撑 | 状态 |
| --- | --- | --- |
| 指定某人某天某岗位，其余自动补 | 编辑页点格子 → 下拉选岗位（班次随岗位自动带）→ 打 🔒 锁 → 「锁定后重新优化」 | ✅ 已可用 |
| 有人请年假（多天） | 申请页录 `请假`（起止日期）→ 批准 → 重新优化，求解器把这段设为硬不可排 | ✅ 已可用 |
| 某人要求某天休息 | 申请页录 `休息申请`（单日）→ 批准 → 同上 | ✅ 已可用 |
| 调班（两人互换） | 逐个改两格即可（编辑时的校验只报提醒不阻断），但要操作两次且中间态难看 | ✅ 可用 → 已加「调班互换」一次完成 |
| 一张白纸先预排、再让系统填空 | 必须先「自动排班」出一版才有格子可编辑 | ⚠️ 绕一下可以 |

关键实现细节（已确认，不用改）：

- 求解器读 `availability_requests` 里 **approved** 的 `leave / rest / unavailable`，
  按天或按班次设为硬约束（`solver.py` `build_problem`）；未批准默认不阻止（可配置）。
- 人工预排的所有行（`source=manual` 或 `is_locked`）会**跨该窗口内所有草稿汇总**后固定进下一次求解，
  所以"我排的"不会被自动改写（冲突时降级为软约束并提示复核）。

### 需要补的两个小动作

1. **原子换班** `POST /api/schedule/versions/{id}/swap`
   body：`{work_date, employee_a, employee_b}`
   在一个事务内交换两人当日的 `position_code / shift / role_code / source`，最后统一校验一次。
   解决"逐个改会 409"的问题，编辑器加一个「互换」按钮（选中两格 → 互换）。
2. **空白预排草稿**（可选）`POST /api/schedule/versions` 建一个只有日期范围、没有安排的空版本，
   编辑页就能先填人工预排，再点「锁定后重新优化」让系统补空。
   不建也能用：先自动排一版再改，只是多一步。

## 二、钉钉排班表导出

### 2.1 原表结构（已逐格解析）

| 位置 | 内容 |
| --- | --- |
| 行 0 | 标题 `柯达广州塔排班表`（新宋体 20 粗体，居中，合并 16 列） |
| 行 1 | `注意：时间必须严格按照现有格式，否则无法识别到钉钉考勤后台`（新宋体 14 粗体） |
| 行 2 | `排班信息：班次A: 09:00-18:00; … ; 休: 当天休息`（一整行，必须原样保留） |
| 行 3 | 表头 `部门 / 用户ID / 工号 / 姓名 / 2026/11/1\n周日 …`（日期单元格内换行，日期+星期） |
| 行 4+ | 每个员工一行；部门固定 `柯达广州塔`，工号为空，格子里是**班次名**或 `休`，未排班留空 |
| 列宽 | 13 / 13 / 8.83 / 11.33 / 13.66 × N（日期列） |
| 人数 | 源表 27 人，系统在职 25 人（源表多 彭冰依、韩育芳，系统没有这两个档案） |

单元格词表只有 18 个（`排班信息` 里定义的），其中源表实际用到 13 个。

验证：日名额 A1=1、B1=2、A2=3、B2=4、A3=1、B3=1、A7=1、B7=1、A8=1、B8=1、AK=1、BK=2 → 合计 19/天；
源表 11/1~11/3 每天实际 `A1柜台 1、B1柜台 2~3、A108柜台 3、B108柜台 4、其余各 1`，完全吻合，
说明映射就是"岗位改名"，没有额外业务含义。

> `排班信息` 里还定义了未使用的 `班次A`、`班次B`、`班次BK`(09:00-18:00)、`班次C108柜台`(15:30-22:00)，
> 导出时**原样保留整行文本**，不要按系统岗位重新生成，否则钉钉可能拒绝。

### 2.3 唯一缺的数据：用户ID

`用户ID` 是钉钉成员 ID（如 `01551052440126367057`），系统里没有这个字段，也推不出来。

方案（最小改动）：

1. `employees` 加一列 `external_user_id VARCHAR(64) NULL`（可空、不参与任何业务逻辑）。
   用启动时的幂等 `ensure_schema()` 补列（PG/SQLite 通用），不引入 alembic 迁移风险。
2. **用这份原表回填**：按姓名匹配，27 行里 25 行能对上（另 2 人在系统里不存在，会列入提示清单）。
   做成 `POST /api/employees/external-ids` 接口 + 员工导入模板加一列，后续新人自己维护。
3. 导出时 `用户ID` 取该字段；为空的行在导出结果里标黄并在响应头/页面提示"N 人缺钉钉ID，导入会失败"。

### 2.4 导出接口

`GET /api/export/versions/{id}/dingtalk.xlsx`

- 新模块 `backend/app/services/dingtalk_export.py`，只读 `schedule_versions / schedule_assignments /
  employees / availability_requests`，不碰求解器。
- 词表与文案放配置 `app_settings["dingtalk_export"]`（默认值即本次解析结果），
  以后岗位改名/加岗位只改配置，不改代码。
- 版本页、总览页各加一个「导出钉钉表」按钮。
- 文件名：`柯达广州塔排班表{start}-{end}.xlsx`。

## 四、已确认的决策（2026-11-06）

1. **请假/年假在表格里统一写「休」**，请假事实由钉钉审批单承载。配置项 `leave_token` 留着，
   以后人力要求区分「年假」时改一个配置即可，无需改代码。
2. **钉钉用户ID 从原表按姓名自动回填**：25 人可对上，`彭冰依`、`韩育芳` 系统里没有档案会列出来。
   映射文件 `backend/tools/dingtalk_ids.json` 含真实员工ID，**已加入 .gitignore 不入库**。
3. **输出 `.xlsx`**。若钉钉导入不认，再考虑补 `.xls` 写库（不建议先做，成本高收益低）。

## 六、使用路径

**人工预排 + 系统补空**
1. 「自动排班」生成一版草稿（保证有格子可编辑）。
2. 「查看/调整」→ 点格子下拉选岗位 → 点 🔒 锁定；需要调班用「调班互换」。
3. 有人请假/指定休息 → 「申请」页录入 → 批准。
4. 回编辑页点「锁定后重新优化」→ 系统补齐其余岗位，锁定行不动。

**上交人力**
版本页 / 总览页点「导出钉钉表」→ 得到 `柯达广州塔排班表YYYYMMDD-YYYYMMDD.xlsx`
→ 直接用钉钉「排班导入」上传。
