## 3. 测试发现并已修复的缺陷

### D-01（严重）主管当值公平口径错误，当值集中在少数人

- **现象**：3 天窗口内 6 位主管抢 3 个当值，实际出现 `{某人:2, 另一人:1, 其余:0}`，极差 2，违反需求 §6.1。
- **根因**：`solver.py` 的公平项把 `role_vars` 全部计入"当值"，而 `role_vars` 同时包含 `early_support`（A2）与 `late_support`（B1）。历史统计 `history["duty"]` 只算 `duty_supervisor`，两侧口径不一致，优化目标与实际统计错位。
- **修复**：公平项只取 `supervisor_role_code == "duty_supervisor"` 的变量（`solver.py:463-490`），与历史统计对齐。
- **验证**：`test_fairness_pairing.py::test_duty_fairness_total_spread` 由失败转为通过；`test_weekend_duty_fairness` 同步通过。
- **修复后实测**（演示库副本，2026-11-05 起 3 天）：当值分布 `{周美玲:1, 陈志强:1, 郑家豪:1}`，极差 **1**，缺口 0，耗时 131ms。
- **影响范围**：所有使用自动排班的版本；此前生成的"当值分配"可能偏向个别主管（涉及额外工资，建议管理员复核已发布历史）。

### D-02（严重）搭班"同班次"偏好在两人可用岗位不相交时完全失效

- **现象**：设置"希望同班"权重 20 后，两名员工三天内同班次数仍为 0，且目标分解中完全没有搭班项。
- **根因**：约束生成时要求"两人在同一岗位上都存在决策变量"才建立表达式。两人技能集合互不相交（例：`{A1,A3,A7,B1,B3,B8}` 与 `{A2,AK,B2,B7}`）时，交集为空，约束根本未被创建，`scope` 参数形同虚设。
- **修复**：改为按"各自班次覆盖"分别累计后取交（`solver.py:529-570`），并真正实现 `same_shift / same_position / same_day` 三种作用范围（此前 `scope` 未生效，一律按同日处理）。
- **验证**：`test_pairing_prefer_brings_employees_together`、`test_pairing_avoid_keeps_employees_apart`、`test_pairing_scope_same_position` 全部通过。
- **影响范围**：历史排班中"避免同班"实际退化为"避免同日"，比主管设定更严格；"希望同班"则完全未生效。

### D-03（中）移动端三类表格被裁切且无法横向滑动

- **现象**：390px 视口下，请假审批、岗位列表、员工搭班偏好三张表右侧内容被卡片 `overflow-hidden` 直接切掉，用户既看不到也无法滑动。
- **根因**：表格外层缺少滚动容器，只有 `Card className="overflow-hidden"`。
- **修复**：统一改为 `.table-scroll` 容器（`globals.css`），并为首列加 `.col-pin` 冻结、为可滚动区域加左右渐隐阴影提示。
- **验证**：`frontend/ui-audit.mjs` 三档视口（390 / 820 / 1440）巡检，全部页面文档级横向溢出 0px；截图 `docs/shots/m-requests.png` 可见右侧渐隐与完整列。

### D-04（中）移动端整体缺乏响应式适配

- **现象**：全站几乎无断点类，390px 下 KPI 卡、三列表格、配置项标签与输入框挤压重叠；人工调整页下拉框文字被切断且无滑动提示。
- **修复**（本轮）：
  - 顶部导航改为**覆盖式抽屉**（带遮罩、点击导航自动收起、退出登录入口）；
  - 小屏表格统一横向滚动 + 首列冻结 + 边缘阴影，避免"把每列挤成不可读"；
  - 统计页在手机上隐藏"区域/班次"冗余列，6 列一屏可读；
  - 人工调整页日期列由 150px 收窄至 116px，新增"← 左右滑动查看三天 → · 姓名列已固定"提示；
  - 按钮强制 `whitespace-nowrap`（此前"录入申请"会折成两行），表单控件移动端最小高度 32px。
- **验证**：`docs/shots/m-*.png` 共 10 张移动端截图 + `m-drawer.png`。

## 6. 需要管理员做业务判断的事项

以下均来自需求文档 §17「待确认事项」，系统已做成配置项而非写死，需要业务方给出正式口径：

1. **月休 8 天的周期**：自然月 / 滚动 28 天 / 自定义周期？跨月是否结转？（当前默认自然月）
2. **主管公平统计周期**是否固定自然月？法定节假日名单由谁维护、提前多久录入？
3. **A2/B2/B1 运营角色是否额外占用岗位名额**？主管能否同日兼任普通岗位？（当前：不额外占名额、不兼岗）
4. **销售岗位"普通员工"口径**：早班实习生/兼职是否计入普通员工人数？（当前：兼职计入、实习生不计）
5. **目标人数与最低人数**是否允许目标高于最低？人数不足时是"允许带缺口草稿"还是"拒绝生成"？（当前：允许草稿，发布需二次确认）
6. **是否允许跨岗兼任 / 同班次内分时段换岗**？（当前：关闭）
7. **旺季、周末、法定节假日标签**的维护方式与责任人。
8. **偏好权重默认值**是否需要按门店实际调整（班次偏好 9、搭班避让 40、当值公平 45…）。
9. **请假批准前是否阻止排班**？（当前：不阻止，仅批准后为硬约束）
10. **旧 Excel 中其他代码**（如 B450）的业务含义；导入时当前标记为"未知代码"，不做猜测。

另需业务确认两项系统行为：

11. **发布带缺口班表**是否必须由主管二次确认（当前：必须，接口 `allow_gap=true`）。
12. **员工每周上班上限**是否需要执行（当前不执行，见 N3）。

**冲突场景手工复现（验证"不伪造满足"）**：

1. 启动服务，登录 `admin / admin123456`；
2. 进入「每日需求」，把某天 `AK` 目标人数改为 30（示例团队仅 31 人）；
3. 「自动排班」→ 生成，总览页该日 `AK` 显示红色缺口标记；
